## Local delta - why this copy differs from the base

1. **Proofs survive a commit that touches only `.specs/`** (from tlc-spec-driven item 2, the verified-commit stamp). `validate_verification.py` compared `proofs.md`'s `**HEAD**` with raw HEAD, so committing the report itself - `proofs.md` and `verification.md`, which `build.md` tells the builder to commit - turned the gate red, and the resume table sent a new session back to `check_proofs.py` on a finished feature. Now only a change outside `.specs/` since the proofs ran makes them stale - the cut lean already applied to `screens.md` (`_code_changed_since`). Docs: `verify.md` "The gate", `memory.md` resume table. A new selftest case proves it (red before the fix). **PR candidate.**
2. **`penalize` guard in lessons.py** (tlc-spec-driven item 4): only a `confirmed` lesson can be penalized - a candidate was never loaded as guidance, so it cannot have failed when applied. Sentence in `memory.md`; new selftest step (red before the fix). **PR candidate.**
3. **`capability-sync` integration** (tlc-spec-driven item 1): `.specs/capabilities/` in SKILL.md's artifact tree and scripts table and in `memory.md`; Plan reads the capabilities a feature touches (`plan.md`); the Verifier receives them and a broken scenario is a finding (`verify.md` "Capabilities the diff touches" - tlc-spec-driven's regression check 2b); after the gate, "Sync capabilities" folds the verified criteria in and must pass `capabilities.py check` (tlc-spec-driven's Step 11). `capability-sync` is ours - it does not exist upstream. Cross-skill references go through the sibling folder, `<skill-dir>/../capability-sync/` (toolbox ADR-0003).
4. **`domain-modeling` bridges** (tlc-spec-driven item 5): Plan reads accepted ADRs (`docs/adr/`) as binding like an active `AD-NNN`, and writes criteria and Shape in `CONTEXT.md`'s terms (`plan.md`). `memory.md` admits an `AD-NNN` by the ADR's three-part test (a convention that fails it goes to `AGENTS.md`), sends vocabulary to `CONTEXT.md`, and makes the `AD-NNN` row a pointer when the substance lives in an ADR or another log. Upstream said "append there instead and do not start a second one", which also fought its own `validate_plan.py`: the gate looks up the `AD-NNN` behind a `Differences from the source` row in `.specs/STATE.md` only. The pointer keeps both true. A departure from a binding source stays an entry whatever the test says, because the gate reads it there. PR candidate in conditional form.
5. **Upstream router to grilling** (tlc-spec-driven item 7): `plan.md` suggests `/grill-with-docs` when the _what_ itself is contested, next to upstream's route for an open architectural bet. Depends on toolbox-local skills - PR candidate only in conditional form.
6. **Expand-contract tip** (tlc-spec-driven item 10): lean has no task phase, so the tip lives in `build.md` "Commit" - a wide mechanical change lands as expand, migrate in batches, contract, every commit green. PR candidate.
7. **Mutants in the Verifier** (2026-11-23, after a side-by-side lab of both skills on one feature; decisions by Lucas). The Verifier mutates every rule that changes an outcome the diff touched - one to three behaviour faults per rule (driven's sensor: one to three per feature, more for P0, a tier lean does not have) that a caller can see; a fault that changes nothing reachable is dropped for another on the same rule, so there is no `equivalent` status. From driven's sensor it keeps a scratch `git worktree`, never `git stash`, no prescribed setup, and a before/after check of the real tree. It departs where four review rounds found holes: the check is a fingerprint taken from the repo root of everything outside `.specs/` (the screens sub-agent writes there in parallel) - `git status`, a hash of `git diff HEAD` and of the untracked files' contents, since `git status` alone misses a mutant left in a file already modified; on a difference nothing is restored (driven says restore, and a checkout or a clean erases the user's work); the `mktemp -d` path is named literally in every step (a shell variable does not survive between tool calls, and `git -C ""` acts on the real tree); the unmutated `Run` group passes first and a canary - the rule's file made to fail to load - goes red, proving the run reads the scratch; one mutant at a time, processes the run started stopped, a run stopped at three times the baseline's time; driven's file-copies fallback is left out, because copies of the mutated files alone cannot run a test group - without git, `## Mutants` reads `None - no git: mutants need a worktree` (SKILL.md "Requires"). When a step cannot be done (no worktree, red baseline, green canary, changed fingerprint), every planned mutant reads `not run` and a `gate_fail` finding says which step stopped. The table is `| Rule | Mutant | Status | Killed by |`: `Status` is `killed`, `survived` or `not run`, and `Killed by` names the test in a code span, in the runner's own form - the state is its own column because rounds 2 to 4 each broke a rule that guessed it from the test name. A survivor is a `weak_test` finding; the builder runs a `survived` or `not run` mutant at the fix commit and writes `killed` with the test that goes red. What still fails goes to the user: a survivor no test can kill gets another fault from the user, which the builder runs; mutants the scratch cannot run are run once the user fixes the setup, or the user writes `None - <why>` and owns it. `validate_verification.py` checks the claim's form, not that the test went red: it reads GFM tables (a row needs no leading `|`) and refuses a report with no `## Mutants` section (a table, or one `None - <why>` line), a table without `Mutant`, `Status` and `Killed by` columns or with no rows, a `Status` other than the three words, a row not `killed`, a `killed` row with no code span in `Killed by`, a row with more cells than its header, and a `|` line outside a table; `split_row` reads `\|` as a pipe inside a cell, as GFM does (moved to `lean_config.py` by item 8). Docs: SKILL.md rule 5, "Who checks what" and "Requires", `verify.md` "The round" step 3, "What the Verifier does", "Mutants", the report template and "The gate", `memory.md` signal table (`weak_test`, `gate_fail`). Selftest: the fixture carries a `## Mutants` table; the cases and controls are marked with this item. Why: in the lab, lean's reading Verifier missed three weak tests that tlc-spec-driven's discrimination sensor killed - a boundary moved one millisecond inside, a removed normalisation, a swapped error code - and two of them were still in lean's final code. It is not the upstream sensor: no `Mutations:` line in `checks.md` (upstream `b9caf0c` dropped that one) and no fix-and-re-verify loop. Breaking: a project whose features were verified before this item owes `## Mutants` - `None - verified before mutants` on those reports (`verify.md` "The gate" and the gate's error say so). Not a PR candidate: it reverses upstream's bet.

8. **Table cells and None declarations read the same in every gate** (2026-11-24, found on a Portuguese plan in the bolso repo). Two bugs, one symptom: `validate_plan.py` passed a plan whose `## Surface` routes it never checked. (a) The plan had an empty header table before the real one. `first_table` read the empty one, and the "no route rows" error was skipped because `NONE_RE` (`\b(none|nothing|n/?a|single module)\b`) matched the Portuguese preposition "na" in the prose, since the `/` was optional. Any "none" in a sentence did the same. `NONE_RE` now needs the declaration to open its line (bullet, bold or code span allowed) and `n/a` to keep its slash. (b) Once the routes were read, cells such as `SYNCED\|NOTHING_NEW` moved the columns: `validate_plan.py`, `validate_checks.py`, `check_proofs.py` and `selftest.py` split on every `|`, while `validate_verification.py` already read `\|` as GFM does (item 7). That one `split_row` now lives in `lean_config.py`, and every script that reads a table imports it. Selftest: two mutants (an empty header table plus "na" before the routes; a Surface whose prose says "none" mid-line) and three controls (an escaped pipe in a Surface cell, a code-span `None - ...` Surface, a Landing bullet that opens with "Nothing"). All were red before the fix, except the two None controls, which guard against the fix going too far. `selftest.py` now imports `split_row`, so it puts its own folder on `sys.path` first: `python3 -I` leaves that folder off, and `pnpm test:py` runs the selftest with `-I` to keep it so. **PR candidate.** The same `split_row` bug is in tlc-spec-driven's `validate_spec.py`, which was not touched here.

9. **`## Findings` reads GFM tables** (2026-11-24, issue #27, second item). `validate_verification.py` read `## Findings` through `find_tables`, which drops a one-row "table" and needs a leading `|`: an open finding written after a blank line, or with no leading `|` under the table, was never read, and the gate passed. `## Findings` now uses `_gfm_tables`, the reader item 7 wrote for `## Mutants`: a row needs no leading `|`, and a line opening with `|` outside a table is an error. Unlike `## Mutants`, a line that only holds a `|` is not: the `None - <what was probed>` line `verify.md` asks for, or a note, may name code such as `string | null`. Docs: `verify.md` "The gate". Selftest: two cases (an open finding after a blank line; one with no leading `|` under the table), both red before the fix, and two controls (a None line and a note holding a pipe), both red before the stray rule was narrowed to lines opening with `|`. **PR candidate.**

Script patches carry a `Local patch (toolbox UPSTREAM.md item N)` comment, so a 3-way merge shows what they are.

## Known difference from upstream

Lean 2.x dropped mutation testing on purpose - upstream `b9caf0c`, 2026-10-30, "run proofs with the project's own test commands and drop mutations". This copy brings a narrower form back, as local delta item 7: the Verifier mutates the rules the diff touched, and the proofs still run with the project's own commands.

## How to update

Same procedure as `skills/tlc-spec-driven/UPSTREAM.md` ("How to update"), with this skill's path and branch: `git archive <commit> 'packages/skills-catalog/skills/(development)/tlc-spec-lean' | tar -x --strip-components=4 -C <tmp>`, commit on `vendor/tlc-spec-lean` as `vendor: tlc-spec-lean X.Y.Z (upstream <full-hash>)`, then `git merge vendor/tlc-spec-lean` on main. The smoke test is `python3 skills/tlc-spec-lean/scripts/selftest.py`: it must end in `0 survived` and `tooling ok`, the local cases included.

**Hard rule:** never edit the skill on the vendor branch - it is pure upstream, always.
