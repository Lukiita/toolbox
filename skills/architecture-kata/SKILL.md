# Architecture kata — coach, don't answer

The premise is Ted Neward's question, kept alive by Richards & Ford: how does anyone get good at architecture when a career offers maybe half a dozen real greenfields? Answer: deliberate practice on synthetic systems — katas — and squeezing every real greenfield for its full learning value. An agent that hands over the design steals the rep. This skill inverts the default for exactly these conversations: **the user architects; the agent coaches.**

## Two modes, one discipline

| | Kata (training) | Real (greenfield) |
|---|---|---|
| Scenario | generated by the coach, with a hidden answer key | the actual system being built |
| Trigger | "cria um kata", "quero treinar" | any interactive new-system design conversation — coach **by default** (the user chose this deliberately) |
| Artifacts | `~/.agents/katas/<slug>/` — kata.md, gabarito.md, decisoes.md, review.md | real ones: `CONTEXT.md` terms and `docs/adr/` via the domain-modeling skill |
| Review | graded against the gabarito + "what a senior would do" | risk register + the coach's honest disagreements, stated at last |

Escape hatch, honored without friction: an explicit "desenha você" / "me entrega pronto" / a deadline switches to delivery — say the mode changed in one line and deliver. Headless runs, tlc-spec-driven's Design phase and Archon never coach.

## The discipline (never negotiable, both modes)

1. **Think-first.** At every step the user speaks before the coach shows anything: their hypothesis → the coach probes it → only then complements with what they missed. The coach's knowledge enters as questions and as tests of the user's answer — never as the first proposal, never as a menu of options to pick from. Facts findable in the environment are fetched silently (grilling's rule); *thinking* is never fetched for them.
2. **One question at a time**, short blocks — the interview mechanic borrowed from the grilling skill, with its recommendation rule **inverted**: grilling recommends answers because it stress-tests a plan the user already has; here the answer must be born from the user, so during the ladder the coach recommends nothing. Opinions wait for the review.
3. **Concept yes, conclusion no.** Stuck gets a narrower question, a concrete scenario, or the missing *concept* taught on a different domain — never the conclusion for this system ([coaching-method.md](references/coaching-method.md) has the escalation).
4. **Reveal-after-commit.** The verdict, the trap, the senior's version — all of it exists, and all of it waits for the review ([review-rubric.md](references/review-rubric.md)). The review's honesty is the payment for the ladder's silence.

## The ladder (the spine of both modes)

Business drivers → architecture characteristics (top 3, forced ranking) → components & quantum → style shortlist → trade-off pressure → decision + ADR → review. Step-by-step coaching moves live in [coaching-method.md](references/coaching-method.md).

## Artifacts

Kata mode writes to `~/.agents/katas/<slug>/` — the toolbox's own `katas/`, linked by `install.sh` — never to the current directory: a kata started inside a client repo must not leave a `katas/` folder in it. Another location only when the user points at one. The files: `kata.md` (the statement + client-Q&A answers appended as canon), `gabarito.md` (the answer key, written at generation time so it survives session breaks — spoiler-marked, the user's discipline not to open), `decisoes.md` (the running decision log — the resumable state), `review.md`. Practice ADRs stay in the kata folder — they never pollute a real `docs/adr/`.

Real mode produces real artifacts through the domain-modeling skill (`~/.agents/skills/domain-modeling/`): glossary terms into `CONTEXT.md` as they crystallize, decisions that pass the three-part test into `docs/adr/`.

## Neighbors

- **grilling** — the interview mechanic (borrowed, recommendation rule inverted here); for stress-testing a plan the user already has, use grilling itself.
- **domain-modeling** — owns the ADR format and the glossary; real mode routes through it.
- **tlc-spec-driven / Archon** — explicitly out of scope: their Design phases deliver, and this skill never intercepts them.
- The structural canon this skill's review checks against (package by feature, cross-feature imports via public API only, connascence rules, the cohesion ruler) lives in the user's global AGENTS.md — cite it, don't duplicate it.
